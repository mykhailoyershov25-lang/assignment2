# Оптимізація запитів у PostgreSQ

### Структура бази даних
База даних імітує роботу платформи електронної комерції та складається з трьох основних таблиць:
* `opt_clients` (100 000 рядків): Дані про клієнтів та їхній статус.
* `opt_products` (10 000 рядків): Інформація про товари та категорії.
* `opt_orders` (1 000 000 рядків): Дані про транзакції, що пов’язують клієнтів і товари.

### 1. Проблема: Неоптимізований запит
**Завдання:** Знайти категорію товарів, на яку було зроблено найменшу та найбільшу кількість замовлень активними клієнтами у 2023 році.

Неоптимізований запит змушує базу даних чотири рази перераховувати один і той самий набір даних за допомогою вкладених підзапитів та `HAVING`.
* **Час виконання:** `Execution Time: 197.420 ms

### 2. Рішення: Етапи оптимізації
Для оптимізації запиту я використав наступні методи:

1. **CTE (Common Table Expressions):** Використано конструкцію `WITH`, щоб об'єднати таблиці та відфільтрувати дані за 2023 рік **лише один раз**.
2. **Віконні функції:** Застосовано `ROW_NUMBER()` для ранжування категорій за один прохід без необхідності повторного сканування таблиць.
3. **Умовна агрегація:** Використано техніку `MAX(...)` разом із `CASE WHEN` для зведення результатів у зручну таблицю.

* **Час виконання оптимізованого запиту:** Execution Time: 63.875 ms
